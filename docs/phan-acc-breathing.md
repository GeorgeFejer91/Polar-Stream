# Phan ACC breathing in Polar Stream Mini

Polar Stream Mini offers two optional LSL outputs adapted from [Lyn Phan's Mobile Phone Breathing Detection](https://lynphan.github.io/Mobile-Phone-Breathing-Detection/) and its [source implementation](https://github.com/lynphan/Mobile-Phone-Breathing-Detection/blob/main/BreathingDetection/Assets/MobilePhoneBreathingDetection.cs). They are **not** enabled by default and do not replace the existing PCA breathing waveform. Raw H10 ACC remains unchanged and is published first.

The source places a phone on the abdomen and reads acceleration at roughly 60 samples/s. For each axis it compares a 12-sample short average (0.2 s) with a 12,000-sample long average (200 s), sums the absolute differences across three axes, and compares the result with an adaptive threshold initialized at 0.05 g. The threshold rises by 0.000005 per source frame above threshold and falls by the same amount below it. A roughly one-second peak buffer and 0.25-second refractory delay suppress repeated counts. Its displayed breaths/min is the number of events in the trailing 60 seconds.

The mini processor uses the same time durations, three-axis difference, 0.05 g threshold, and equivalent 0.0003 g/s threshold slope on the H10's 200 Hz ACC source timestamps. A rising threshold crossing is counted after at least one second below threshold and the 0.25-second refractory delay. This is an intentional event-gating correction: the upstream `goingDown` flag can remain set after a sustained peak and skip a subsequent breath. The processor uses bounded rolling sums (40 short and 40,000 long samples), so raw publication never waits for a scan of a 200-second window. Gaps over one second, clock resets, and reconnects clear its averages, event history, and threshold. There is no interpolation or imputation across missing ACC data.

- `<base>_phanBreathEvent`: irregular `Markers` stream, value `1` only on a detected event; silence means no event, not a device disconnect. The sample is published with the newest timestamp of the BLE notification containing the crossing.
- `<base>_phanBreathRate`: irregular `Respiration` stream, rolling count of detected events in the previous 60 seconds, in breaths/min. It is emitted once per accepted ACC notification, including an initial value of zero while the history fills.

In single-stream mode, these are sparse `phanBreathEvent` and `phanBreathRate` channels on metric rows in the existing combined Polar outlet. Changing the selections while connected stages new outlets without restarting BLE. The saved choice is restored on the next launch. Source-loss markers remain the mini's separate status mechanism; neither breathing output invents values while ACC is absent.

**Interpretation limit:** The source method was demonstrated on an abdomen-mounted phone, not a chest-strap H10. Strap rotation, posture changes, heartbeat motion, and general movement can cause false events or missed breaths. Synthetic tests establish implementation behavior only; physical comparison against a synchronized respiratory reference is still required before treating this as a measured respiratory rate. The app is research software, not a medical device.
