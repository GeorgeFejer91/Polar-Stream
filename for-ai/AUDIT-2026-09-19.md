# Repository audit — 2026-09-19

## Scope and baseline

This audit covers the current working tree at commit `66c5759` on
`codex/consolidated-current-feature`, including uncommitted and untracked mini
app work. It reviewed Rust/Tauri ownership and IPC, output timing and lifecycle,
frontend and test pressure, CI/release surfaces, and the complete `for-ai/`
instruction set. Generated build trees, caches, packaged binaries, and private
artifacts were excluded.

The tree was already materially dirty before this audit. Findings therefore
describe the observed working tree and are not attributed to this documentation
change. Revalidate every finding against the eventual review commit.

## Findings

### P1 — Single-stream mini output changes source timing

`LslOutlet::monotonic_newest` advances a repeated or overlapping candidate by
`period * record_count` (`crates/polar-h10-output/src/lsl.rs:154-168`). The new
combined publishers reuse that one outlet clock for ECG, ACC, HR/metrics, and
for Vernier raw plus derived breathing (`:715-780`, `:938-1115`).

Those streams overlap in source time. For example, a Vernier raw batch and its
derived breathing batch carry the same newest timestamp, but the second push is
forced at least one complete batch later. Polar ECG and ACC chunks are likewise
serialized after one another even when their source intervals overlap. This
distorts timestamps, inflates the combined timeline, and violates the raw-time
contract.

Required next slice: keep single-stream mode unavailable until a timestamp-
ordered merge owns all row types, or redesign the one-outlet contract so rows
are emitted once in source-time order. Add deterministic tests for overlapping
ECG/ACC chunks and same-batch Vernier raw/derived rows.

### P1 — Vernier can report streaming after output setup failed

`run_vernier_session` emits `OUTPUT_CONFIGURE_FAILED` when schema/outlet setup
fails, but then unconditionally emits `streaming: true` and the message that raw
channels and breathing are publishing (`crates/stream-mini-runtime/src/lib.rs:
1274-1306`). In single-stream mode the publisher can have no outlet at all, so
this is a false readiness claim.

Required next slice: make successful schema/outlet creation a prerequisite for
the streaming event, and tear down or enter an explicit connected-but-output-
failed state when it cannot be established.

### P1 — Disconnect failure drops the only task/output owner

`disconnect_active` removes the active session before awaiting provider cleanup
and returns immediately on cleanup failure (`crates/stream-mini-runtime/src/
lib.rs:1096-1118`). The join handle is then dropped without join or abort, while
the state no longer has a session to retry or finish cleaning up. This can leave
a detached task/output owner after a timeout or platform error.

Required next slice: retain cleanup ownership until join/abort completes on
both success and failure, then publish one terminal state. Add timeout and
provider-error tests.

### P2 — Failed live reconfiguration is persisted as if accepted

`save_preferences` writes the new snapshot before attempting live output
configuration (`crates/stream-mini-runtime/src/lib.rs:715-775`). If output
configuration fails, the command returns `OUTPUT_RECONFIGURE_FAILED`, but the
new file remains durable while the active session still uses the old settings.
The next launch can therefore apply a change that the UI saw fail.

Required next slice: validate/configure first and commit preferences only after
acceptance, or restore the previous snapshot on failure. Cover disk state,
active state, and restart state in one focused test.

### P2 — New mini contracts have no focused Rust tests

The workspace suite reports zero unit tests for `stream-mini-runtime` and both
mini app crates. Existing lower-layer tests are strong, but they do not exercise
the combined-stream clock, preference transaction, output-readiness, or cleanup
contracts above. The defects are therefore compatible with a green workspace
test and clippy run.

Required next slice: add tests only around these current contracts. Do not build
a generalized mini-app test framework.

### P2 — The mini bootstrap exposes an unused absolute resource path

`MiniBootstrap` serializes `lsl_resource_path`, populated with the resolved
native filesystem path (`crates/stream-mini-runtime/src/lib.rs:573-583` and
`:683-703`). Neither mini frontend reads it. The presence boolean is sufficient;
the absolute path unnecessarily exposes installation details to the WebView.

Required next slice: remove the path from the IPC response and retain only the
capability/status value.

## Instruction and maintainability observations

- The repository previously named the mandatory skill as `tauri-rust developer`
  while the installed identifier is `tauri-rust-developer`. `AGENTS.md` and the
  new `SKILLS.md` now route the exact known identifier; older historical/context
  mentions remain and should be normalized in a separate context-cleanup slice.
- No Pony Tail/Ponny Tail skill is installed in the current environment. The
  requested rule is recorded in `SKILLS.md` and intentionally blocks future
  coding rather than pretending the skill ran.
- `START-HERE.md` and `PROJECT-CONTEXT.md` hard-code a Linux checkout path even
  though the active canonical checkout is on Windows. Repository identity
  should be expressed by remote plus resolved repo root, not one machine path.
- The mandatory build/install/publish/live-Pages rule applies to every edit,
  including instruction-only changes. That is broader than the affected
  surfaces and can conflict with external-publication authorization or a dirty
  worktree. Narrow it in a separate policy decision; do not silently bypass it.
- `check-context.sh` checks presence and a legacy skill-name substring, but not
  `SKILLS.md`, platform-neutral paths, contradictory instructions, freshness,
  or the scope of deployment requirements.
- High-pressure files include `apps/polar-stream/ui/app.js` (8,630 lines),
  `crates/polar-h10-input/src/windows_backend.rs` (5,311),
  `apps/polar-stream/src/lib.rs` (2,258), and
  `crates/polar-h10-output/src/lsl.rs` (1,836). Treat these as change-risk maps,
  not automatic refactor requests.
- The two mini `app.js` files differ by only eight lines out of 501 and their
  stylesheets are byte-identical. This is drift pressure, but YAGNI says not to
  consolidate until a real change or defect requires shared ownership; built
  assets may remain app-local.

## YAGNI remediation order

1. Correct or disable single-stream publication and prove timestamp order.
2. Fail closed on Vernier output readiness and preserve cleanup ownership.
3. Make live preference changes transactional.
4. Add only the focused tests needed for those three contracts.
5. Perform a separate instruction-cleanup slice for portable paths, exact skill
   names, deployment scope, and stronger context validation.

Do not combine these fixes with a frontend decomposition, dependency refresh,
or general mini-UI deduplication.
